# InneR Algorithm Testing

In point-reach, the robot (first `action_dim` state dimensions) moves towards the goal (next `action_dim` state dimensions), and the remaining state dimensions are irrelevant noise; `state_dim` and `action_dim` are set in `config.py` (16 and 4 by default). The expert moves straight towards the goal, one unit per step at most. The dataset is a set of expert demonstrations: from a random initial state, the expert moves towards the goal for `n_steps` steps (set in `config.py`, 40 by default) and every (state, action) pair along the way is a datapoint, so `n_demos` demonstrations (100 by default, set in `get_dataset.py`) give `n_demos * n_steps` datapoints. The test scripts roll out the learned policies the same way, from 1000 random initial states for `n_steps` steps. `bash.sh` collects one dataset, then trains and tests two kinds of policy on it; `./bash.sh SEED` runs everything with a different seed (dataset, initial weights, batch order, and test states), so repeated runs give independent samples. Each has a baseline (model 0) and InneR (model 1). Two norm-regularization baselines (models 2 and 3) are also implemented, the Frobenius and nuclear norms of the Jacobian for the MLP and their Fisher-information analogues for the diffusion policy, but they are disabled by default because they were worse than the baseline in every earlier test. A third disabled model (4) is InneR-C, the ablation of InneR without clustering from Section VII of the paper: Algorithm 1 with k = B, so the one region is the whole batch, and the average inner product (or Fisher information) of the batch is regularized with the same weight `GAMMA` as InneR. The three `train_model` calls at the bottom of each training script are commented out, and the test scripts only roll out the models listed in their `MODEL_NAMES` dictionary (0 and 1). To run them, uncomment the calls and add `2: "Frobenius", 3: "nuclear", 4: "InneR-C"` to `MODEL_NAMES`.

`config.py` also sets `dynamic_goal`. With `dynamic_goal = False` the goal indices are fixed, so every state is robust to the same perturbations and a global regularization of A or F makes sense. With `dynamic_goal = True` the goal depends on context, like the stacking task in the paper: if the last state entry (the switch) is negative, the goal is instead the `action_dim` entries after the default goal, so `state_dim` must be larger than `3 * action_dim`. The switch is never changed by a rollout, so the goal of each datapoint and test rollout is fixed, but the relevant state directions differ between the two contexts.

`config.py` also sets `scramble_state`. With `scramble_state = True` (off by default) the policies do not see the axis-aligned state above but a scrambled one, z = A2 phi(A1 s + b1) + b2 (`StateScramble` in `models.py`, the first step of `forward()`): a random invertible matrix A1 and offset b1, a bend phi of each entry, and a random rotation A2 with offset b2. The robot, the goal, and the noise are no longer separate entries of the policy input, and the task-relevant information is spread across every entry, but none of it is lost, because every layer is invertible. `scramble_condition` bounds the ratio of the largest to the smallest singular value of A1 (1 gives a pure random rotation; 10 by default, which also stretches some directions), `scramble_shift` the range of b1 and b2, and `scramble_bend` the bend: phi_i(x) = x + c_i tau tanh(x / tau) with c_i uniform in [-`scramble_bend`, `scramble_bend`] (0.5 by default) and tau = 5, whose slope lies between 1 - |c_i| and 1 + |c_i|, so phi is strictly increasing for a bend below 1. The Jacobian A2 diag(phi') A1 then has condition number at most cond(A1) (1 + bend) / (1 - bend). With `scramble_bend = 0` the scramble is affine, z = A1 s + b1, and the affine layer of a seed is the same with and without the bend. The transformation is drawn from the seed of a run (`randomize()`), so it is the same for every model of that run and differs between seeds, and it is stored in the policy as buffers and saved with the weights, so each model is tested with the transformation it was trained with. The dataset and the test rollouts are unchanged, since the environment itself stays axis-aligned; the training scripts only convert the policy Jacobian or score from the environment state to the scrambled state (`jacobian()`, the chain rule), so InneR regularizes the policy with respect to the state it actually sees. With `scramble_state = False` the transformation is the identity and everything is as before.

`config.py` also sets `correlated_noise`. With `correlated_noise = True` (off by default) `get_dataset.py` ties every irrelevant entry of a demonstration's initial state to one coordinate of the active goal (`correlate_noise()`; the k-th noise entry to goal coordinate k mod `action_dim`), mixing the entry's own uniform draw with that coordinate so that their Pearson correlation is 0.9 (the value is set in `get_dataset.py`; `correlate_noise()` takes any value between 0, independent, and 1, a copy of the goal coordinate). No extra random numbers are drawn, so the robot and goal entries, and the expert actions, are the same as without it for the same seed. The test scripts keep drawing independent uniform states, so the correlation exists only in the training data, and a policy that reads the goal from the noise entries as a shortcut fails at test time. With the dynamic goal and `state_dim = 3 * action_dim + 1` there are no noise entries, and the option does nothing.

## Files
- `config.py`: `state_dim`, `action_dim`, `dynamic_goal`, the rollout length `n_steps`, the network width `hidden_dim`, the state scrambling (`scramble_state`, `scramble_condition`, `scramble_shift`, `scramble_bend`), and the correlation of the noise entries with the goal in the training data (`correlated_noise`), shared by every script
- `get_dataset.py`: collects the dataset of expert demonstrations (`datasets/dataset.pkl`) shared by both policies
- `models.py`: `StateScramble` draws (`randomize()`, from `random_affine()`) and applies the scrambling transformation inside both policies and converts derivatives to the scrambled coordinates (`jacobian()`); its buffers are saved with the weights, and weights saved before it existed load with the identity. `MLPPolicy` maps the state to an action. `DiffusionPolicy` learns to predict the noise added to an action (DDPM), and `sample()` turns gaussian noise into an action with DDIM (10 steps at test time, 1 inside the Fisher estimate)
- `train_mlp_policy.py`: model 0 uses standard BC, model 1 adds InneR with the policy Jacobian, and models 2 and 3 (off by default) are the Jacobian regularization baselines from Section IV of the paper (squared Frobenius norm and nuclear norm of J, each with its own weight), and model 4 (off by default) is InneR-C, InneR with the whole batch as the one region; saved as `models/mlp_weights0` to `models/mlp_weights4`
- `train_diffusion_policy.py`: model 0 uses the default diffusion policy loss, model 1 adds InneR with the Fisher information, and models 2 and 3 (off by default) are the Fisher analogues of the Jacobian-norm baselines (trace of F, and nuclear norm of the scores, i.e. the sum of the square roots of F's eigenvalues), and model 4 (off by default) is InneR-C, InneR with the whole batch as the one region; saved as `models/diffusion_weights0` to `models/diffusion_weights4`
- `test_mlp_policy.py`, `test_diffusion_policy.py`: roll out each model in `MODEL_NAMES` for `n_steps` from the same initial states (and, for diffusion, the same sampling noise), and report the average distance to the goal and the success rate of the paper (final distance below one expert action). The tests only load the saved weights, so they can be rerun without retraining

## InneR
Both training scripts group every state of a batch with its `K_NEIGHBORS = 8` nearest neighbors by the alignment of their active subspaces (the distance between the rank-r projections), average a matrix over each neighborhood, and penalize the ratio of its n - r smallest eigenvalues to the total of all eigenvalues (with the total detached, so the loss cannot be lowered by growing the large eigenvalues). The rank r is the action dimension m for the MLP and `FISHER_RANK = 2m` for the diffusion policy. The eigenvalue ratio is computed by `inner_loss()` in each script, which InneR-C (model 4) applies to the average over the whole batch instead of the neighborhoods. The matrix is:
- MLP: A(s) = J^T M J, from the policy Jacobian J
- diffusion: the Fisher information F(s) (Section V of the paper). For every state, `get_fisher_information()`:
  1. samples actions from the current policy, a ~ pi(. | s), without gradients
  2. estimates the score g(a, s) = grad_s log pi(a | s) with the gradient of the ELBO, -T grad_s E[lambda_t * l(a, s; t, eps)] (Equation 21), drawing t from a proposal q(t) that favors low noise levels and weighting each draw by 1 / (T q(t)), which keeps the estimate unbiased
  3. averages g g^T over the sampled actions to get F(s) (Equation 17)

## Notes
- The Fisher-norm baselines of the diffusion policy use `GAMMA_FROBENIUS = 1e-4` and `GAMMA_NUCLEAR = 1e-3`.
- The Jacobian-norm baselines of the MLP use `GAMMA_FROBENIUS = GAMMA_NUCLEAR = 0.01`.
- The regularization weight `GAMMA` is 0.2 for the MLP and 0.3 for the diffusion policy Larger weights make the regularizer dominate early in training, when the Jacobian or Fisher is still small, collapsing every state onto one shared null space.
- The Fisher rank `FISHER_RANK` is set to twice the action dimension. The action dimension is only a lower bound on the rank of F(s) for a stochastic policy, and overestimating the rank is the safe direction: it penalizes fewer eigenvalues, whereas underestimating it penalizes directions the policy needs. `N_ACTION_SAMPLES` equals the rank so that each F(s) can reach it.
- `N_NOISE_SAMPLES` trades accuracy for speed: with few (t, eps) samples, the noise in the score estimate adds a positive bias to F(s), which shrinks as more samples are used.
- The dataset consists of whole expert demonstrations of the same length as a test rollout, so it covers the approach, the last steps, and the goal itself, where the test rollouts spend most of their time (the start is 16 units from the goal on average and at most 40, so the expert reaches the goal within `n_steps` and the later datapoints of most demonstrations sit at the goal with a zero action).
- Both trainers use a fixed batch of 200 datapoints, so the number of gradient steps grows with the dataset; the MLP trains for 200 epochs and the diffusion policy for 1000, and each saves its model every 100 epochs.
- The MLP trains on the CPU, where this small network is faster than on a GPU. The diffusion policy trains on the GPU if one is available.
- The scrambled state keeps roughly the scale of the environment state: A stretches by at most sqrt(`scramble_condition`) in any direction, the bend by at most 1 + `scramble_bend`, and A2 is a rotation, so the networks need no input normalization.
- The dataset (`datasets/dataset.pkl`) and the saved weights (`models/`) are written by `bash.sh`, and every run overwrites them.

## Speed
Measured on 5 Nov 2026 (28 logical CPU threads, RTX 4060, torch 2.15) with the default config, n = 16 and B = 200. The training steps are close to their floor; the gains are in how the runs are scheduled.
- The MLP step is too small for many threads: one InneR training is fastest at 4 threads (6.2 ms per step), the torch default of 14 is slower (6.5 ms), and 28 threads nearly doubles the time (11.4 ms). Run many trainings at once with few threads each instead: 14 concurrent trainings at 2 threads each (`OMP_NUM_THREADS=2`, or `torch.set_num_threads(2)` in the driver) give 707 steps per second in total against 104 for one process at 14 threads, i.e. 6.8 times the throughput; 7 trainings at 4 threads give 4.2 times. Each run needs its own working copy, because the scripts write `datasets/` and `models/` relative to the current directory.
- The diffusion policy sets the schedule (about 9 ms per InneR step against 2.6 ms for BC, and 5 times the epochs of the MLP). One training uses 145 MiB of GPU memory and leaves gaps between its small kernels, so 2 concurrent trainings give 1.36 times the throughput and 4 give 1.48 times; beyond that the GPU is saturated. Keep 4 CPU threads per diffusion process to launch its kernels.
- The running loss averages of the diffusion trainer are accumulated on the device and converted only at the 100-epoch print: the earlier `.item()` at every step made the CPU wait for the GPU, which cost 6 percent of the InneR step. The MLP trainer keeps `.item()`, which costs nothing on the CPU.
- Where a diffusion InneR step goes (7.0 ms isolated): denoising loss 0.6 ms, sampling the N_a actions 0.7 ms, the score estimate 1.7 ms, SVD plus Grassmann distances plus top-k 0.8 ms, the eigendecomposition of the neighborhood averages with its backward 0.7 ms, and the double backward through the scores plus the optimizer step about 2.5 ms. The linear algebra is already a minor share.
- Tried and not worth it: deterministic algorithms off on the CPU (no change); one batched autograd call for the Jacobian instead of the loop over the m rows (6.09 against 6.15 ms); moving the diffusion SVD, distances and eigendecomposition to the CPU (12.6 against 7.0 ms per step, every piece is 2 to 3 times slower on the CPU at n = 16; the CUDA batched SVD is fast through n = 32 and only becomes 50 times slower from n = 33); `torch.compile` of the denoiser (its compiled backward refuses the `create_graph=True` that the score estimate needs); replacing the DataLoader with tensor slicing (saves 0.26 ms per batch, 3 percent of an InneR step, but changes the batch order of every seed).

## Install and Run

```bash
# Everything runs from this folder (the scripts use relative paths to datasets/ and models/)
cd single_integrator/toy_environment

# Create and source virtual environment
python3 -m venv venv
source venv/bin/activate

# Install dependencies
pip install numpy torch

# Run the script (optionally with a seed, default 0; the seed is passed to every script)
# bash.sh calls python3, so the virtual environment must be active
./bash.sh
```
